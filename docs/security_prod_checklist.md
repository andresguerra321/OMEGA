# Checklist de Seguridad para Despliegue en Producción (`NEEDS-VALIDATION`)

Este documento consolida los 6 puntos `NEEDS-VALIDATION` de la auditoría defensiva de **OMEGA** (`NV-A1`..`NV-C2`) que dependen de la configuración del entorno desplegado (variables de entorno, proxy inverso, red Docker y reglas de GitHub).

| ID | Componente | Requisito en Producción | Verificación / Comando exacto |
|---|---|---|---|
| **NV-A1** | `backend-java` (`JwtService`, `ProductionSecurityStartupValidator`) | Ejecutar con `SPRING_PROFILES_ACTIVE=prod` y `OMEGA_JWT_SECRET` aleatorio de ≥ 32 bytes (distinto al valor de desarrollo). El validador `prod` bloquea el arranque si falla. | `docker exec omega-backend env \| grep -E '^(SPRING_PROFILES_ACTIVE\|OMEGA_JWT_SECRET)='` (verificar `prod` y longitud ≥ 32 bytes: `printf '%s' "$OMEGA_JWT_SECRET" \| wc -c`). |
| **NV-A2** | `backend-java` (`SessionCookieHelper`) + Reverse Proxy | Configurar `OMEGA_COOKIE_SECURE=true` (verificado al arrancar en `prod`) y garantizar que el proxy inverso sobrescribe `X-Forwarded-Proto: https` en lugar de confiar en el valor enviado por el cliente. | `curl -sI https://<dominio>/api/v1/auth/csrf \| grep -i 'set-cookie'` (confirmar atributo `Secure`) y revisar `proxy_set_header X-Forwarded-Proto $scheme;` en Nginx/Caddy/Traefik. |
| **NV-B1** | `backend-java` (`application.yml`, Tomcat RemoteIP) | Configurar `server.forward-headers-strategy=native` (o `framework`) y restringir `server.tomcat.remoteip.internal-proxies` exclusivamente a la subred del proxy inverso para que `getRemoteAddr()` no sea falsificable en `LoginRateLimiter`. | Revisar `SERVER_FORWARD_HEADERS_STRATEGY` y `SERVER_TOMCAT_REMOTEIP_INTERNAL_PROXIES` en `.env` / Compose, y probar que enviar un `X-Forwarded-For: 1.2.3.4` externo no altera la IP registrada. |
| **NV-B2** | `backend-java` (`RepoScannerProxyController`, `MultimodalThreatQueryService`) + `omega/api` | Confirmar que `omega/api` solo es alcanzable desde `backend-java` (que propaga `X-Tenant-Id` tras validar propiedad en `DevScanRepository`) y documentar el número de réplicas de `backend-java` si se escala horizontalmente el rate limit público multimodal. | `docker compose ps` y prueba negativa contra `GET /api/v1/repo/scan/<uuid-otro-tenant>` esperando `404 Not Found`. |
| **NV-C1** | `omega/api` (`main.py`, Docker network) | Configurar `OMEGA_REQUIRE_HMAC=true`, aislar el puerto `8000` en red interna Docker (sin `ports:` publicados en `0.0.0.0`) y fijar límite de cuerpo HTTP en el proxy/ASGI (`OMEGA_MAX_HMAC_BODY_BYTES`). | `docker ps --format '{{.Names}} {{.Ports}}' \| grep omega-api` (sin exposición pública en `8000`) y `docker exec omega-api env \| grep -E '^(OMEGA_REQUIRE_HMAC\|OMEGA_MAX_HMAC_BODY_BYTES)='`. |
| **NV-C2** | GitHub Repository Settings (`release-desktop.yml`) | Proteger el entorno `release` en **GitHub Settings → Environments → `release`** exigiendo revisores requeridos (*Required reviewers*), política de despliegue restringida exclusivamente a tags `v*` (*Deployment branches and tags*) y almacenar `RELEASE_SIGNING_KEY` como secret del entorno `release` (no a nivel de repositorio). | `gh api repos/<owner>/<repo>/environments/release` y verificar `protection_rules` + `deployment_branch_policy.custom_branch_policies == true`. |
